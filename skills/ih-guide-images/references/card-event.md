# 打牌活动：计算与推荐模块

适用：周活动中消耗卡片、随机取得英雄卡并组队闯关的机制，例如历史 Card Clash of Illusion。活动换名时按实际机制判断；觉醒盛典、抽卡召唤或仅带卡牌装饰的活动不因此适用。与打牌联动的积分在这里核对，独立觉醒品质积分仍分开分析。

本模块保存分析方法，不提供下一周可直接套用的礼包价格、卡量、关卡目标或概率。项目路径相对仓库根；纯分析到文案交付即可，制图另按 [攻略图技能](../SKILL.md)。

## 先确定本周参数

制作新一周时按主技能的公告和分析来源核对；仅整理已有资料或修改确认文案时，无需重查。记录活动期、来源链接、读取时间，分清公告事实、社区经验、用户建议、推算和待确认项。相同数字的旧说法被纠正后，只用最新有效口径计算，保留旧稿作追溯。

从本周资料提取实际用到的字段，缺失值标为待确认，不填零：

| 项目 | 需要核对 |
| --- | --- |
| 卡片来源 | 登录、任务、钻石购买、绑钻直接购买、绑钻礼包、现金礼包直接赠卡、VIP月夜累计档位赠卡；各自卡量、价格、次数上限及领取条件 |
| 玩家起点 | 当前卡片、已消耗卡片、已买礼包、已领取奖励、当前关卡、可用资源、剩余领取天数；无玩家数据时明确采用全周新起点 |
| 通关 | 每关奖励、是否一次性、是否为累计表、随机耗卡、手动/扫荡的差异及解锁条件 |
| 联动积分 | 各积分来源、基础上限、倍率作用位置、奖励门槛、VIP档位是否累计；明确各积分单位 |
| 兑换 | 商店解锁条件、累计消费或持有数量、折扣次数、购买上限及目标奖励 |

只有会影响推荐的缺口才阻止相关结论；其余部分可以先算。没有本周耗卡依据时可给出供卡能力与条件收益，不能给出确定可达关卡。

## 卡量：把库存、上限和预计需求分开

给每个来源独立记账，礼包直接赠卡与VIP累计赠卡各列一行，只有确认两者独立才相加。档位表先判断是累计总额还是逐档增量；累计总额只取已达最高档，不能逐档相加。未满足的领取条件不得计入确定可用卡。

- 从当前状态计算：`计划可用卡 = 当前库存 + 尚未领取且可获得的免费卡 + 本方案新增购卡 + 本方案新增赠卡`。当前库存已含的卡和已领VIP赠卡不再加一次；耗卡需求也必须是从当前关卡到目标的剩余需求。
- 从全周新起点计算：使用全周来源总量和全程预计耗卡，不能再叠加中途库存。
- `来源剩余额度 = 本周上限 − 已购数量`，按对应单位核算；出现负值先查数据或单位，不静默归零掩盖矛盾。
- `卡片缺口 = max(0, 预计剩余耗卡 − 计划可用卡)`。若耗卡是区间，分别算区间两端的缺口；区间不是置信区间或成功率。

“买满后的供卡上限”单独列出，不写成必须购买量。按实际进度补缺口；先判断剩余额度能否补齐，再比较资源代价。购买以整包计，遇到不同卡量、阶梯价格或联动VIP档位时逐个组合计算，不能用一个平均单价取整代替。

某渠道买满后不能再建议同渠道超限补卡。其他补充渠道只有本周确认可用时才列出；无可行渠道就降低目标或明确无法补齐。资源消耗分列钻石、绑钻、现金等，不自行折成一个“总成本”。

## 通关与积分：分别计算，再合并收益

- 单关奖励表按已通关关卡累加；累计奖励表取目标档值，不再次累加。玩家中途咨询时分别注明全程累计奖励和从当前进度新增奖励，已领取的不算新增收益。
- 将打牌消耗积分、觉醒次数积分、觉醒品质积分分别记账。获得卡片不等于消耗卡片，觉醒次数不等于品质分；未知的积分来源不补猜。
- 先按本周规则算各来源积分、来源上限及总上限，再按明确规则应用倍率和奖励表。倍率可能作用于积分或奖励，不能默认两者都乘，也不能把积分翻倍当作所有奖励翻倍。
- 对每种奖励分别合计：`总收益 = 通关收益 + 联动收益 + 其他已满足条件的收益`。避免同一奖励既列在礼包中又列在联动中。兑换收益另算，消耗掉的宝库币不能同时保留为兑换后净收益。
- 联动要求觉醒等额外投入时，明确其资源前提；不能只列购卡费用却暗示所有积分条件已自动达成。兑换解锁按本周规定的累计消费或持有数量计算，折扣只覆盖规定次数。

手动和扫荡分别评估。只有手动经验支持的路线必须写明“手动打牌，勿用扫荡”；不能因礼包解锁了扫荡就认定扫荡同样省卡，也不能自动把一条路线的结论扩展到另一条。

## 比较方案与写推荐

每个方案分别核算现金礼包直接卡、累计VIP新增赠卡、积分倍率、钻石/绑钻投入及可补卡渠道。同价、同VIP经验不代表同供卡量；社区方案与用户方案礼包不同，不能直接移用关卡或收益范围。

依据用户库存和目标比较“新增投入能换来什么”，不固定推荐免费/小氪/高氪各一条。保留有实际区别的路线；如方案只提高倍率但减少供卡，需要同时呈现，不能只看宝库币理论总额。

用户问某个现金礼包“最多能有多少张卡”时，默认含义是：购买该现金礼包，并把当周登录、任务、钻石、绑钻直购、绑钻礼包和已达到的VIP月夜赠卡等较低成本来源全部拿满；答复中列出各来源。只有用户明确问“礼包本身”或“该礼包带来的增量”时，才只算直接卡与由它触发的VIP里程碑。不要把其他现金礼包计入这个“一个礼包”的方案。

每条推荐交付：**目标关卡 → 投入组合 → 可获得收益 → 必须满足的条件 → 不确定性/补缺口方式**。可用简表或连贯文案，不要求固定版式。详细账目留在当周笔记；成图保留手动要求、积分前提、额外资源投入与条件收益，不能为精简删除。

通关消耗取决于随机性和操作。历史估算标明出处与适用条件；用户经验可以作为推荐依据，但不写成统计验证的“小概率”或无条件保底。不套用上一周固定关卡、觉醒目标或付费评价。
