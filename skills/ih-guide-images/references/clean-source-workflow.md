# 从干净素材和可编辑源稿重制

适用于需要修改攻略文案、避免连续整图编辑损伤细节的场景。2026-09-10用户要求用现有文案彻底重做中英文图，并在可行时更新技能；用户随后确认采用1200×1600、居中水印，并授权推送本版。

## 已验证示例

当前用户选择为`output/weekly-event-2026-09-11/fresh-v17/`的1200×1600双语版：复用v16素材，以1倍像素密度直接渲染；水印中心(600,800)、68px字、逆时针10°、7.5%不透明度，文字置于水印上层。`node output/weekly-event-2026-09-11/fresh-v17/build.mjs`可重新导出；文案与v16一致，不重新调用图像生成模型。当前周图默认尺寸与居中水印规则已同步更新至技能入口。

当前可复现源文件均随本次提交保存：

- `output/weekly-event-2026-09-11/fresh-v17/copy.json`：当前确认中英文文案。
- 同目录`build.mjs`：读取文案与原始素材，创建自包含HTML，在隔离Chrome中以1倍像素密度渲染。等待字体及图片解码后截图，检查主要容器溢出、资源卡正文与标签遮挡、水印数量和中心。
- `output/weekly-event-2026-09-11/fresh-v16/header-original.png`与`header-prompt.txt`：仅生成一次的干净插画及提示词。
- `output/weekly-event-2026-09-11/icons/`：原始游戏资源及来源映射；公会Logo复用`flipgame/assets/guofeng-guild-logo.png`。
- 正式站内图片：`flipgame/images/weekly-event-2026-09-11.png`及`weekly-event-2026-09-11-en.png`。

从仓库根目录重新导出：

```bash
node output/weekly-event-2026-09-11/fresh-v17/build.mjs
```

导出生成同目录的`weekly-event-2026-09-11-{zh,en}-v17.html`和`.png`，以及`qa/report.json`、局部检查截图。这些预览、截图和报告不作为源文件提交；正式站内PNG从验收后的输出复制。此前已验证同源2倍导出2400×3200可行，但当前不默认输出大尺寸。

此示例使用项目`flipgame/node_modules/playwright`和本机Google Chrome；其他环境采用实际可用的渲染器，不为匹配示例擅自安装或切换服务。页面不读取CSV/JSON、不访问外部网络，数据和素材已嵌入，因此导出的独立HTML可用本地文件方式渲染。需要fetch的站内页面仍按根AGENTS.md启动HTTP服务。

## 可复用的结论

此次文字、边框、底色和水印均为源稿里的独立元素，背景只生成一次，Logo和道具图标直接嵌入原文件；没有使用v15整图作为输入。布局调整后重新渲染，不会让模型重新解释已有文字和边缘。图像素材自身的质量仍需要单独验收。

验收包括中英文整图及100%原尺寸局部、实际1200×1600尺寸、无容器溢出、单处水印、原始Logo，以及5,000钻石、300–350绑钻、80/120币、1,500分和手动勿扫荡等条件。用户后续的风格反馈仍应回到源稿修改；发布授权按当次请求执行，不沿用本次授权。
